## 1. Centralización de Valores en el Proyecto (Anti-Hardcoding)
Evitar escribir cadenas, dimensiones y colores fijos directamente en el código de Compose (*hardcoded values*).

### Archivos de recursos en `res/values/`:
1. `strings.xml`: Cadenas de texto internacionalizables.
   ```xml
   <resources>
       <string name="app_name">Contador de clics</string>
       <string name="btn_clickme">¡PÚLSAME!</string>
       <string name="counter_text">Has hecho clic %1$d veces</string>
   </resources>
   ```
2. `colors.xml`: Paleta de colores en hexadecimal (`#AARRGGBB` o `#RRGGBB`).
   ```xml
   <resources>
       <color name="teal_200">#FF03DAC5</color>
       <color name="primary_red">#FFE53935</color>
   </resources>
   ```
3. `dimens.xml`: Medidas, rellenos y tamaños de fuente reutilizables.
   ```xml
   <resources>
       <dimen name="button_text">25sp</dimen>
       <dimen name="btn_padding">16dp</dimen>
   </resources>
   ```

## 2. Consumo de Recursos en Jetpack Compose mediante la Clase `R`
Compose proporciona funciones puente para leer valores centralizados:
- **Textos:** `stringResource(id = R.string.btn_clickme)`
- **Colores:** `colorResource(id = R.color.primary_red)`
- **Dimensiones:**
  - Para `dp`: `dimensionResource(id = R.dimen.btn_padding)`
  - Para `sp` (tipografía): `dimensionResource(id = R.dimen.button_text).value.sp`

### Cadenas con Parámetros Dinámicos:
Declaración en XML:
```xml
<string name="user_points_text">Hola %1$s, has conseguido %2$d puntos</string>
```
Llamada en Kotlin / Compose:
```kotlin
Text(
    text = stringResource(R.string.user_points_text, userName, userScore)
)
```

## 3. Internacionalización (Multi-Idioma)
Android gestiona el multi-idioma mediante carpetas de recursos con sufijos de localización (*locale qualifiers*):
- `res/values/strings.xml`: Idioma por defecto (habitualmente inglés o español base).
- `res/values-es/strings.xml`: Idioma castellano / español.
- `res/values-ca/strings.xml` o `values-va/`: Valenciano / Catalán.
- `res/values-en/strings.xml`: Inglés.

> **Regla de resolución:** Si una clave no se encuentra en el archivo del idioma activo del dispositivo, el sistema recurre al valor definido en el `strings.xml` por defecto (*fallback*).

## 4. Control de Orientación (Screen Orientation)
Para forzar o bloquear una orientación específica en una pantalla, se añade el atributo en `AndroidManifest.xml` dentro del nodo `<activity>`:
```xml
<activity
    android:name=".MainActivity"
    android:exported="true"
    android:screenOrientation="portrait">
    <!-- Configuración bloqueada en vertical -->
</activity>
```
- Valores posibles: `portrait` (vertical), `landscape` (horizontal), `unspecified` (libre).

## 5. Depuración y Logs (Logcat)
Android Studio integra un sistema de trazabilidad y logging:
```kotlin
Log.i("CONTADOR_APP", "Se ha pulsado el botón. Valor actual: $times")
```
- Niveles de log: `Log.v` (Verbose), `Log.d` (Debug), `Log.i` (Info), `Log.w` (Warn), `Log.e` (Error).
- Visualización: Ventana inferior **Logcat** en Android Studio filtrando por etiqueta (*tag*).

## 6. Resolución de Problemas Comunes en Android Studio
- **Versión de Java / JDK en Gradle:** Si falla la sincronización de Gradle, revisar:  
  `File → Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK` (asegurar compatibilidad con Java 17 o 21 según la versión de Gradle/AGP).
- **Librería appcompat:** Necesaria si se combinan temas o componentes tradicionales de Android Views con Jetpack Compose.
