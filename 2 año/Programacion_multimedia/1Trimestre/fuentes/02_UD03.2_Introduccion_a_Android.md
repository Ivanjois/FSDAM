## 1. Estructura Inicial de un Proyecto Compose
En un proyecto generado con la plantilla *Empty Activity*, la clase principal contiene:
```kotlin
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            ContadorDeClicsTheme {
                Scaffold(modifier = Modifier.fillMaxSize()) { innerPadding ->
                    Greeting(
                        name = "Android",
                        modifier = Modifier.padding(innerPadding)
                    )
                }
            }
        }
    }
}
```

### Elementos clave:
- `ComponentActivity`: Clase base que soporta Jetpack Compose.
- `setContent { ... }`: Define el árbol composable que conforma la interfaz de la Activity.
- `Scaffold`: Contenedor estructural de Material Design con soporte para top bar, bottom bar, FAB y padding interno (`innerPadding`).
- `@Composable`: Marca cualquier función que renderiza componentes en pantalla.
- `@Preview`: Permite inspeccionar la vista en el editor de diseño sin compilar ni desplegar en un emulador físico.

## 4. Gestión del Estado en Compose (`State`)
Una variable local convencional (`var times = 0`) no notifica al runtime de Compose que debe repintar la UI cuando cambia su valor.

### Paso 1: Variable de estado reactiva con `remember`
```kotlin
var times by remember { mutableStateOf(0) }
```
- Cuando `times` incrementa (`times++`), Compose detecta la mutación y recompone únicamente los componentes que leen `times`.

### Paso 2: Persistencia ante la destrucción de la Activity (`rememberSaveable`)
- Al rotar la pantalla, cambiar de tema o idioma, la `Activity` se destruye y se recrea.
- Con `remember`, el estado se pierde y vuelve a su valor inicial (`0`).
- Con `rememberSaveable`, el valor se almacena en el `Bundle` del sistema y sobrevive a recreaciones de configuración:
```kotlin
var times by rememberSaveable { mutableStateOf(0) }
```
